Remediation ladder

Do not force SFT; earn it

Use the cheapest control that makes the failure stop recurring. Customization is one rung, not the first move.

01

Runtime config

Disable thinking leakage, normalize provider quirks, and make the contract shape stable.

Start with repeatable infrastructure behavior.

02

Prompt + schema

Clarify when tools apply, when to stop, and what the required JSON response must contain.

Use explicit contracts before model changes.

03

Guardrails

Put deterministic policy in code: preconditions, idempotency, retries, and audits.

Use code for behavior that must never drift.

04

SFT

Use when behavior should travel with an open-weight model and resists prompt or guardrail fixes.

Customize only after the evidence supports it.

The honest result is valuable: some failures need prompts, some need code, and only some justify model customization.

Tool-Calling Consistency Lab

Takeaways

What to take back to your own agents

Reliable tool use comes from measured behavior, shared contracts, and deterministic controls around the model.

Measure traces

Capture requests, tool calls, tool results, and final responses before debating fixes.

Make accepted behavior explicit.

Replay failures

Turn surprising behavior into reviewable evidence and repeatable regression gates.

Preserve the evidence, not just the anecdote.

Use the ladder

Start with configuration, prompts, schemas, and guardrails. Use SFT only when behavior must travel with the model.

Fix each failure at the lowest durable layer.
